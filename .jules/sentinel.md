## 2024-07-06 - [CRITICAL] Prevent DoS & Database Errors via FormData Type Bypassing
**Vulnerability:** Next.js Server Actions were blindly casting `formData.get('field') as string`. A malicious user could submit a file upload (which parses as a `File` object) instead of a text string, bypassing the TypeScript cast and causing unexpected behavior or errors later when string methods are called. Additionally, there was no length limitation, allowing a DoS or Prisma database error from excessively large payloads.
**Learning:** `formData.get()` returns `FormDataEntryValue` (`File | string | null`). The `as string` cast in TypeScript only suppresses compiler warnings but does not check the type at runtime. Next.js Server Actions process raw FormData securely only when explicit runtime type checking is used.
**Prevention:** Always use a utility function (like `getValidString`) that explicitly checks `typeof value === 'string'` and enforces reasonable length constraints (e.g., 255 chars) before processing data in Server Actions. Never blindly cast `FormData` entries.
