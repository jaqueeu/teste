## 2024-03-21 - [DoS & Type Bypass in Server Actions]
**Vulnerability:** Next.js Server Actions directly casted `formData.get('field')` using `as string`. This allowed an attacker to bypass type checking by submitting a `File` object (which is valid for `formData.get()`), leading to unexpected backend errors. Additionally, there were no length constraints on the inputs, which could lead to DoS attacks by sending massive payloads, or cause Prisma database insertion errors when exceeding database column limits.
**Learning:** Next.js `FormData` methods return `FormDataEntryValue` (which is `File | string | null`). Using `as string` merely tells TypeScript to ignore the potential `File` type, but does not actually convert or validate the data at runtime, leaving the backend exposed.
**Prevention:** Always use a validation utility (like the newly added `getValidString`) to explicitly check `typeof value === 'string'` and enforce a maximum length before passing the data to the database or other logic.
