## 2024-07-05 - FormData Type Bypass and DoS in Next.js Server Actions
**Vulnerability:** Next.js Server Actions extracting `FormData` values were using `as string` type assertions (e.g., `formData.get('name') as string`). This is dangerous because `formData.get()` can return a `File` object if the client sends a file upload or crafts a malicious multipart request. This bypasses TypeScript's type checking, potentially causing application crashes or unexpected behavior when string methods are called on the `File` object. Furthermore, there was no length limitation, allowing an attacker to submit massive strings (e.g., 50MB) which could cause a Denial of Service (DoS) due to memory exhaustion or database errors (Prisma) when attempting to insert.
**Learning:** Never trust `FormData` input types or lengths in Server Actions. Blindly asserting `as string` is a critical anti-pattern.
**Prevention:** Created a reusable utility `getValidString(formData, key, maxLength)` that explicitly checks `typeof value === 'string'` and strictly enforces a length limit using `.slice()`. This utility must be used for all string extractions from `FormData`.
