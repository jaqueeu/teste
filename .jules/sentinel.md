## 2025-02-12 - Next.js Server Actions FormData parsing and Type Cast Vulnerability
**Vulnerability:** The application was extracting variables from `formData` using `formData.get('field') as string;`. This unsafe cast blind trust on input types allows malicious actors to send `File` objects which will bypass the typecast during runtime (which is stripped during compilation), causing potential DoS when the application tries to stringify/parse a large file. Also, lacking a string length constraint allows overly large strings that can crash the app or throw unhandled database constraints errors.
**Learning:** `formData.get()` returns `FormDataEntryValue | null`, which can be either a `string` or a `File` object. Blindly using `as string` in TypeScript only hides the type error at compile time but doesn't prevent a `File` object from being passed to Prisma or other APIs at runtime.
**Prevention:** Always explicitly check `typeof value === 'string'` for `formData.get()` returns. A reusable validation utility function like `getValidString` was created in `src/lib/validation.ts` to safely extract, type-check, and enforce length constraints on `FormData` strings in Server Actions. Never blindly cast inputs using `as string`.
